# ASAP-G1-Learning: G1 机器人强化学习与 Sim2Sim 学习记录

本项目基于 [ASAP](https://github.com/LeCAR-Lab/ASAP) 框架，记录我在 **Unitree G1** 上做强化学习、动作模仿和 Sim2Sim 验证的实践过程。  
重点不是“堆功能”，而是尽量把几条链路真正跑通：

- 复杂动作模仿训练
- 奖励与控制参数排障
- Isaac Gym → Genesis / MuJoCo 的 Sim2Sim 验证
- 面向动力学差异的残差补丁实验
- 基于 RL 的足球单次击球 / 颠球任务

> **注**：原项目官方说明已重命名为 `README_ORIGIN.md`，便于单独查阅环境配置和基础使用方法。

## 🛠️ 已完成的技术工作

### 1. 动作模仿训练与奖励调整

为了让 G1 更稳定地学会爆发性动作（例如 CR7 Siuuu 起跳），我主要做了这些调整：

- **加入力矩课程学习**：开启 `soft_torque_curriculum`，早期给更高力矩上限帮助模型探索起跳发力，后期再逐步收回到 `0.85`，解决了“完全不起跳”的问题。
- **处理单脚赖地的局部最优**：训练中一度出现“单脚死踩地、另一脚敷衍抬起”的代偿动作。后续通过降低跌倒惩罚、提高脚部位置跟踪奖励，才让模型更愿意真正双脚离地。
- **抑制手臂乱挥**：增大 `penalty_action_rate`，让关节输出更平滑，减少起跳时靠手臂“乱甩”来补平衡的情况。
- **约束落地脚掌姿态**：加入 `penalty_feet_ori`，让脚掌落地时尽量更平、更稳，降低落地失控概率。

### 2. 控制与训练策略上的调整

- **高噪声断点续训**：模型在约 25k 轮后出现动作发僵、起跳不够干脆的问题。后续在加载已有权重的同时重新拉高探索噪声（`init_noise_std=0.85`），相当于“强行让它重新多试一轮”，对动作高度和舒展度有帮助。

### 3. Sim2Sim 验证链路

为了验证策略是否真的有物理泛化能力，我补了原仓库里缺失的跨引擎验证流程：

- **模型导出与推理**：新增 `humanoidverse/export_pt_to_onnx.py`，并搭建 `genesis_simulation/` 目录，支持 ONNX 策略在 Genesis 中直接测试。
- **Genesis 中的动力学差异排查**：发现同样的 0.85 力矩限制，在 Isaac Gym 中可以完成腾空，而在 Genesis 中会明显损失高度。这说明不同引擎在接触、阻尼、积分方式上的差异会直接影响动作结果。
- **重新启用域随机化**：早期模型在 Isaac Gym 里动作完整，但到 Genesis 经常抽搐摔倒。后续重新加入域随机化后，Genesis 中的稳定性和动作完整度有明显改善。
- **MuJoCo 链路补齐**：目前已经补齐 MuJoCo ONNX 推理流程，并对齐了控制频率、动作滤波、目标限速等关键参数。现在 MuJoCo 已经从“直接抽搐倒地”改善到“可以正常起步，但在起跳前后仍会失稳”。

### 4. 残差补丁（Residual Patch）实验

这部分主要是在研究：  
**当策略从 Isaac Gym 切到 Genesis 后，如果动力学不一致，能不能给旧策略外挂一个小补丁来减小 gap。**

#### 4.1 从纯 RL 残差转向 Oracle 残差

早期我尝试过直接让 46 维 Attention-Delta 网络配合 PPO 去学 `Isaac -> Genesis` 的差异，但很快发现：

- 样本效率很差
- 很容易学到“不摔倒优先”的奇怪代偿
- 在高刚度 PD 和接触不连续场景下很不稳定

后面改成了先求一个局部的“Oracle 残差”：

\[
\delta a^* = (J^T W J + \lambda I)^{-1} J^T W r
\]

也就是先用局部动力学雅可比和加权岭回归，在固定状态上算出“当前最合理的补偿动作”，再让网络去学它。这样做比直接黑盒 RL 更可控。

#### 4.2 离线蒸馏与 OOD 问题

围绕 $\pi^\Delta(s, a_{base})$ 做了多轮 fixed-state 蒸馏实验。  
前期样本少时，网络容易把数值噪声也学进去，甚至在 OOD 状态下放大错误。后续加入了：

- `Lower-Body Masking`
- `Deadzone Filtering`
- 补丁幅值限制

之后在 512 / 1024 样本规模上，离线误差才开始稳定优于 baseline，大约提升 **4%~5%**。  
这也说明单帧状态本身存在表达上限，接触和相位历史很难完全靠单帧补全。

#### 4.3 闭环执行问题定位

把冻结补丁接回闭环执行后，日志里出现了比较大的执行偏移和力矩饱和。进一步确认后发现：

- 代码里的 `max_delta_scale = ±0.10` 硬限制本身是生效的
- 真正的问题在于高 `K_p` 关节下的高频抖动
- PD 扭矩尖峰会把补丁放大成 `Bang-Bang` 式震荡

所以后面的结论很明确：  
这个补丁不能当“大修正器”，更适合做**小范围、低频、保守**的动作微调。后续幅值还需要继续压小，并考虑低通滤波。

#### 4.4 清理实验混杂因素与 PPO bug

为了做干净的 A/B 对比，我额外做了两件事：

- 清理“补丁环境”里偷偷放宽的 termination threshold 和 gap reward，避免把环境变化误当成补丁收益
- 修复了 PPO 底层 `learn_sigma=False` 实际不起作用的问题：原实现里 `std` 仍被注册成 `nn.Parameter`，后续改成 `register_buffer` 后，关闭学习方差才真正生效

#### 4.5 当前结论

在清理混杂因素后，用“旧主策略 + 冻结补丁”做 one-step gap 验证，指标能从 `2.02` 稳定降到 `1.81`。  
这说明残差补丁在**局部动力学层面**确实有作用，不是日志假象。

但问题也很明确：  
虽然局部 gap 变小了，旧策略的整体动作风格还是偏保守，说明瓶颈已经不只是“补丁好不好”，而是**旧主策略还有没有继续适应的可塑性**。

### 5. 足球单次击球 / 颠球任务进展

这是最近新增的一条任务线，目标是让 G1 在仿真里学会用右脚把球踢起，并逐步扩展到连续颠球。

目前已经完成的部分：

- **最小 robot + ball simulator**：没有直接复用 HOI 的 table / tote / cube 场景，而是单独做了一个更轻量的 `robot + ball` 仿真器。
- **single-hit 状态机环境**：任务被拆成 `PRE_CONTACT -> CONTACTED -> POST_CONTACT_EVAL` 三个阶段，reset、termination、reward 都围绕“第一次有效触球”来设计。
- **无屏调试链**：由于服务器环境下不方便依赖 GUI，我额外做了 1-env headless rollout 调试，把球位置、脚位置、终止原因等关键信号落盘排查。
- **接触检测逻辑迭代**：早期严格依赖 pairwise rigid contact，但 GPU pipeline 下并不稳定；后续改成基于 tensor 可用信号的近似检测，并针对“脚部几何与 body origin 不重合”问题，进一步调整了 body 集合和距离门控。
- **训练进入早期有效阶段**：目前已经出现少量“右脚正确首次触球”的样本，说明链路已经从“完全碰不到球”走到了“开始偶尔碰对”。接下来重点是提高触球频率，并把球真正踢到目标高度区间。

## ⚠️ 还在继续做的事

- [ ] **Root 级误差补偿**：当前残差补丁已经能改善 `dof_pos / dof_vel` 层面的 gap，但对 `root` 级轨迹改善还不够，后续需要更直接地约束质心和整体姿态。
- [ ] **MuJoCo 相位与接触对齐**：继续排查 `cycle_time / time_offset`、地面接触参数、XML 动力学与执行器配置，缩小 MuJoCo 与 Genesis / Isaac Gym 之间的差异。
- [ ] **多步 rollout 量化**：目前 one-step gap 的量化已经完成，下一步计划补长时 rollout 指标，例如存活步数、累计 tracking error、root/body/joint 分项误差。
- [ ] **历史信息建模**：当前残差补丁主要依赖单帧状态，后续需要评估 frame stacking、历史动作/速度上下文、显式接触特征，看是否能继续提高补丁效果。
- [ ] **补丁执行平滑化**：闭环测试已经表明，小补丁也可能在高 `K_p` 下被放大成扭矩尖峰。后续还要继续压缩补丁幅值，并尝试低通滤波、动作速率约束和 torque-aware regularization。
- [ ] **Tabula Rasa 主策略重训**：当前一个核心问题是，旧 PPO 主策略可能已经形成固定的代偿动作风格。下一步打算在挂载冻结补丁的环境中，从随机初始化重新训练主脑，验证是否能摆脱旧策略惯性。
- [ ] **足球任务从单次击球走向连续颠球**：目前 single-hit 已经起步，后续目标是提高触球成功率，并扩展到多次连续控制。
- [ ] **更多自定义动作数据**：后续准备自己标注更具挑战性的动作，例如羽毛球杀球（Smash），并继续做 Sim2Sim 验证。
