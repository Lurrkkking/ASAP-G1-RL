# ASAP-G1-Learning: G1 机器人强化学习、动作模仿与 Sim2Sim 实验记录

本项目基于 [ASAP](https://github.com/LeCAR-Lab/ASAP) 框架，记录我在 **Unitree G1** 上做强化学习、动作模仿和 Sim2Sim 验证的实践过程。  
这里不追求“看起来做了很多”，而是尽量把几条链路真正跑通、把问题讲清楚：

- 复杂动作模仿训练
- 奖励设计与控制参数排障
- Isaac Gym → Genesis / MuJoCo 的 Sim2Sim 验证
- 面向动力学差异的残差补丁实验
- 基于 RL 的足球击球 / 颠球任务重构与迭代

> **注**：原项目官方说明已重命名为 `README_ORIGIN.md`，便于单独查阅环境配置和基础使用方法。

## 🛠️ 已完成的技术工作

### 1. 动作模仿训练与奖励调整

为了让 G1 更稳定地学会爆发性动作（例如 CR7 Siuuu 起跳），我主要做了这些调整：

- **加入力矩课程学习**：开启 `soft_torque_curriculum`，早期给更高力矩上限帮助模型探索起跳发力，后期再逐步收回到 `0.85`，解决了“完全不起跳”的问题。
- **处理单脚赖地的局部最优**：训练中一度出现“单脚死踩地、另一脚敷衍抬起”的代偿动作。后续通过降低跌倒惩罚、提高脚部位置跟踪奖励，才让模型更愿意真正双脚离地。
- **抑制手臂乱挥**：增大 `penalty_action_rate`，让关节输出更平滑，减少起跳时靠手臂“乱甩”来补平衡的情况。
- **约束落地脚掌姿态**：加入 `penalty_feet_ori`，让脚掌落地时尽量更平、更稳，降低落地失控概率。

### 2. 控制与训练策略上的调整

- **高噪声断点续训**：模型在约 25k 轮后出现动作发僵、起跳不够干脆的问题。后续在加载已有权重的同时重新拉高探索噪声（`init_noise_std=0.85`），相当于“强行让它重新多试一轮”，对动作高度和舒展度有帮助。

### 3. Sim2Sim 验证链路

为了验证策略是否真的有物理泛化能力，我补了原仓库里缺失的跨引擎验证流程：

- **模型导出与推理**：新增 `humanoidverse/export_pt_to_onnx.py`，并搭建 `genesis_simulation/` 目录，支持 ONNX 策略在 Genesis 中直接测试。
- **Genesis 中的动力学差异排查**：发现同样的 0.85 力矩限制，在 Isaac Gym 中可以完成腾空，而在 Genesis 中会明显损失高度。这说明不同引擎在接触、阻尼、积分方式上的差异会直接影响动作结果。
- **重新启用域随机化**：早期模型在 Isaac Gym 里动作完整，但到 Genesis 经常抽搐摔倒。后续重新加入域随机化后，Genesis 中的稳定性和动作完整度有明显改善。
- **MuJoCo 链路补齐**：目前已经补齐 MuJoCo ONNX 推理流程，并对齐了控制频率、动作滤波、目标限速等关键参数。现在 MuJoCo 已经从“直接抽搐倒地”改善到“可以正常起步，但在起跳前后仍会失稳”。

### 4. 残差补丁（Residual Patch）实验

这部分主要是在研究：

**当策略从 Isaac Gym 切到 Genesis 后，如果动力学不一致，能不能给旧策略外挂一个小补丁来减小 gap。**

#### 4.1 从纯 RL 残差转向 Oracle 残差

早期我尝试过直接让 46 维 Attention-Delta 网络配合 PPO 去学 `Isaac -> Genesis` 的差异，但很快发现：

- 样本效率很差
- 很容易学到“不摔倒优先”的奇怪代偿
- 在高刚度 PD 和接触不连续场景下很不稳定

后面改成了先求一个局部的“Oracle 残差”：

$$
\Delta a^* = (J^\top W J + \lambda I)^{-1} J^\top W r
$$

也就是先用局部动力学雅可比和加权岭回归，在固定状态上算出“当前最合理的补偿动作”，再让网络去学它。这样做比直接黑盒 RL 更可控。

#### 4.2 离线蒸馏与 OOD 问题

围绕 $\pi^\Delta(s, a_{base})$ 做了多轮 fixed-state 蒸馏实验。  
前期样本少时，网络容易把数值噪声也学进去，甚至在 OOD 状态下放大错误。后续加入了：

- `Lower-Body Masking`
- `Deadzone Filtering`
- 补丁幅值限制

之后在 512 / 1024 样本规模上，离线误差才开始稳定优于 baseline，大约提升 **4%~5%**。  
这也说明单帧状态本身存在表达上限，接触和相位历史很难完全靠单帧补全。

#### 4.3 闭环执行问题定位

把冻结补丁接回闭环执行后，日志里出现了比较大的执行偏移和力矩饱和。进一步确认后发现：

- 代码里的 `max_delta_scale = ±0.10` 硬限制本身是生效的
- 真正的问题在于高 `K_p` 关节下的高频抖动
- PD 扭矩尖峰会把补丁放大成 `Bang-Bang` 式震荡

所以后面的结论很明确：

这个补丁不能当“大修正器”，更适合做**小范围、低频、保守**的动作微调。后续幅值还需要继续压小，并考虑低通滤波。

#### 4.4 清理实验混杂因素与 PPO bug

为了做干净的 A/B 对比，我额外做了两件事：

- 清理“补丁环境”里偷偷放宽的 termination threshold 和 gap reward，避免把环境变化误当成补丁收益
- 修复了 PPO 底层 `learn_sigma=False` 实际不起作用的问题：原实现里 `std` 仍被注册成 `nn.Parameter`，后续改成 `register_buffer` 后，关闭学习方差才真正生效

#### 4.5 当前结论

在清理混杂因素后，用“旧主策略 + 冻结补丁”做 one-step gap 验证，指标能从 `2.02` 稳定降到 `1.81`。  
这说明残差补丁在**局部动力学层面**确实有作用，不是日志假象。

但问题也很明确：  
虽然局部 gap 变小了，旧策略的整体动作风格还是偏保守，说明瓶颈已经不只是“补丁好不好”，而是**旧主策略还有没有继续适应的可塑性**。

### 5. 足球任务：从 single-hit 到“前方控球区”重构

这是今天重点重构的一部分，也是目前最值得记录的过程。

#### 5.1 第一阶段：先把最小 single-hit 链路搭起来

最开始我做的是一个比较直接的单次击球任务，目标是：

- 机器人从准备姿态出发
- 用右脚完成第一次有效触球
- 再看球是否被踢到合理高度

为此我完成了：

- **最小 robot + ball simulator**
- **single-hit 状态机**
  - `PRE_CONTACT_PREP`
  - `PRE_CONTACT_SWING`
  - `CONTACTED`
  - `POST_CONTACT_EVAL`
- **无屏调试链**
  - 在服务器 headless 环境里输出球位置、脚位置、终止原因等关键信号
- **接触检测逻辑**
  - 从 rigid contact 查询逐步改成 tensor 可用的近似信号
  - 处理了“脚部几何与 body origin 不重合”的问题

这一阶段的收获是：

- 链路从“完全碰不到球”推进到了“开始偶尔碰对”
- 说明仿真器、状态机、接触检测、reward 和 reset 这些基本件已经能工作

但随着实验往前推，也逐渐暴露出 single-hit 框架的问题。

#### 5.2 single-hit 框架的问题开始暴露

随着 reward 和状态机越加越细，我越来越明显地感觉到：

- 任务在被写成“碰一次球并打分”
- 而不是“真正把球维持在前方一个可控状态里”

具体表现为：

- phase 越拆越细，工程上能跑，但语义越来越像“写一个规则拼装器”
- reward 逐渐碎片化，哪里不对就补一个 reward
- 即便球能被踢起，也很容易出现：
  - **勾脚硬挑**
  - **斜上方抽飞**
  - **踢过头**
  - **踢完后下一拍越来越难接**

也就是说，这一版更像“single-hit benchmark”，而不是我真正想做的“原地自然控球”。

#### 5.3 今天的核心重构：把任务从“单次击球”改成“维持前方控球状态”

今天最大的改变，不是简单改几个 reward，而是**重新定义任务抽象**。

我现在更认同的任务描述是：

> 机器人不是为了“完成一次击球”而击球，  
> 而是为了**把球维持在身体前方一个可控状态区内**。  
> 当球因为重力和误差离开这个区时，机器人需要进行一次修正。  
> 而颠球，本质上就是这种修正手段。

所以我在新目录里开始搭新的任务壳子：

- `ball_control_task/`

而不再继续往旧的 `hitball_task.py` 上硬堆逻辑。

#### 5.4 新框架：先搭 2 态，而不是一开始就上复杂层级

新的高层任务先收敛成两个 mode：

- `REPOSITION`
- `CONTROL_TOUCH`

含义分别是：

- **REPOSITION**：球不在理想状态时，机器人进行补位/回位/准备下一次修正
- **CONTROL_TOUCH**：当时机合适时，执行一次触球修正，把球送回理想状态区

这里我没有再单独拆一个 `RECOVER` 状态，而是先把“恢复/回位”并入 `REPOSITION`，避免一开始又把状态机写复杂。

这一步的目标不是追求终极任务效果，而是先把**新的高层语义骨架**搭出来。

#### 5.5 只保留一个“目标状态区”，不再单独造第二个触球区

新框架一开始也试过“目标区 + 触球区”双层设计，但后来发现还是容易把逻辑重新写复杂。  
所以今天最终收敛成：

**只保留一个目标状态区。**

这个“目标状态区”定义为：

- `x / y`：使用机器人 `base heading frame` 下的相对坐标
- `z / v_z`：使用世界坐标

也就是说：

- x/y 反映“球是否还在机器人前方可控位置”
- z/vz 反映“球在真实世界里是否仍处于可持续控球状态”

这样可以避免机器人本体上下起伏时，把球的 z/vz 状态判断搞乱。

最终的目标状态区不再只是位置区，而是一个**状态区**：

- 球的位置在合理范围内
- 并且球的竖直速度不能继续明显向下掉

这一点非常关键。因为只看位置会出现假象：

- 球位置还在前方
- 但其实已经在往下掉
- 如果此时还算“控制成功”，那是有问题的

#### 5.6 mode 切换也随之简化

现在的逻辑被尽量压缩成下面的闭环：

- 球**离开目标状态区**，且 `v_z` 满足下落条件  
  → 进入 `CONTROL_TOUCH`
- 一旦发生一次 **target contact**  
  → 回到 `REPOSITION`

也就是说：

- 不再依赖第二个独立“触球区”
- 不再要求复杂的 pre-contact 几何门槛
- 只围绕“球是否还在目标状态里”来决定是否要修正

这比之前那套 single-hit/pre-contact 的语义更统一。

#### 5.7 reward 也随之重写成“功能层”而不是“拼装式打分”

今天这次重构里，reward 也尽量朝更少、更清楚的方向收敛。

当前新 `ball_control_task` 里，主要保留这些功能性 reward：

- `reposition_zone_reward`
  - 在 `REPOSITION` 下把球往目标位置拉回去
- `ball_in_target_state_zone_reward`
  - 全局通用，只要球处于目标状态区就加分
- `control_touch_contact_bonus`
  - 正确触球给奖励
- `ball_horizontal_vel_penalty`
  - 惩罚球的水平速度，防止斜飞
- `ball_overshoot_penalty`
  - 球高于目标区上边界时惩罚，防止踢过头
- `missed_target_state_cycle_penalty`
  - 一次修正之后，如果球从头到尾都没真正回到目标状态区，则惩罚
- `penalty_action_rate`
  - 作为全局平滑正则

这和最初 single-hit 那种“contact 后再开一个评估窗口打分”的思路已经不一样了。  
现在更像是在问：

- 球有没有被送回理想状态区
- 球有没有被踢歪
- 球有没有被踢过高
- 这次修正到底算不算成功

#### 5.8 当前阶段的结论

今天这次重构的价值，不在于“任务已经训成了”，而在于：

**把“颠球”从一个一次性的 single-hit 问题，重新表述成了一个更像技能闭环的控球问题。**

现在的新框架还很早期，甚至目前也存在“都不去踢球”的问题。  
这说明高层抽象虽然更清楚了，但要真正学出触球行为，还需要补足：

- 更直接的脚-球几何观测
- 更连续的“正在接近触球”型 shaping
- 后续再加入 motion prior 作为风格层，而不是上来就把 tracking 和功能层混在一起

所以，今天的重构更像是：

- **先把任务定义理顺**
- 再在这个更清楚的框架上继续学会“怎么真正把球踢起来”

我认为这一步是必要的，因为如果任务定义本身就不顺，后面 reward 和 tracking 只会越补越乱。

## ⚠️ 还在继续做的事

- [ ] **Root 级误差补偿**：当前残差补丁已经能改善 `dof_pos / dof_vel` 层面的 gap，但对 `root` 级轨迹改善还不够，后续需要更直接地约束质心和整体姿态。
- [ ] **MuJoCo 相位与接触对齐**：继续排查 `cycle_time / time_offset`、地面接触参数、XML 动力学与执行器配置，缩小 MuJoCo 与 Genesis / Isaac Gym 之间的差异。
- [ ] **多步 rollout 量化**：目前 one-step gap 的量化已经完成，下一步计划补长时 rollout 指标，例如存活步数、累计 tracking error、root/body/joint 分项误差。
- [ ] **历史信息建模**：当前残差补丁主要依赖单帧状态，后续需要评估 frame stacking、历史动作/速度上下文、显式接触特征，看是否能继续提高补丁效果。
- [ ] **补丁执行平滑化**：闭环测试已经表明，小补丁也可能在高 `K_p` 下被放大成扭矩尖峰。后续还要继续压缩补丁幅值，并尝试低通滤波、动作速率约束和 torque-aware regularization。
- [ ] **Tabula Rasa 主策略重训**：当前一个核心问题是，旧 PPO 主策略可能已经形成固定的代偿动作风格。下一步打算在挂载冻结补丁的环境中，从随机初始化重新训练主脑，验证是否能摆脱旧策略惯性。
- [ ] **ball_control_task 短训验证**：验证新的 2 态“控球状态区”框架是否真的能学会把球送回目标状态区，而不是停留在“状态机会切、reward 非 0”的阶段。
- [ ] **加入脚-球几何观测**：如果当前 ball_control 仍然“不去踢球”，下一步优先补充球相对右脚的位置/速度观测，而不是先堆 tracking reward。
- [ ] **在功能层稳定后再加入风格层**：后续计划按“上半身 / 下半身 / 脚踝”逐步接入 tracking 先验，但前提是新框架先证明自己在功能上能工作。
- [ ] **更多自定义动作数据**：后续准备自己标注更具挑战性的动作，例如羽毛球杀球（Smash），并继续做 Sim2Sim 验证。
